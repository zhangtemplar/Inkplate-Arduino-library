# Inkplate 13SPECTRA Digital Picture Frame

This project turns Inkplate 13SPECTRA into an SD-backed photo frame with optional web syncing and a browser configuration UI.

## SD Card Layout

Format the SD card as FAT/FAT32. The sketch creates these paths automatically:

- `/frame/config.json` for settings
- `/frame/photos/` for local photos
- `/frame/config_mode.txt` as an optional boot trigger for config mode

Supported local image types are `.bin`, `.jpg`, `.jpeg`, `.png`, and `.bmp`. JPG, PNG, BMP, and converter-generated BIN files automatically use landscape or portrait orientation based on image aspect ratio. For best quality and the most reliable sync, use `.bin` files generated by `tools/convert_to_inkplate13spectra_bin.py`. If `photo.bin` exists beside `photo.jpg`, `photo.jpeg`, `photo.png`, or `photo.bmp`, the frame displays the `.bin` file and skips the common-image sibling during Drive sync.

## Google Drive Folder Sync

The frame syncs from a Google Drive folder through the included `google_drive_apps_script.gs` web app. The Drive folder can stay private; the Apps Script runs as your Google account and the Inkplate authenticates with a shared token.

1. Create a Google Drive folder for frame photos.
2. Open Apps Script, paste `google_drive_apps_script.gs`, and set `FOLDER_ID` plus `SYNC_TOKEN`.
3. In the Apps Script editor, select `manifestOutput` and click Run once. Grant the requested Drive permissions as the script owner.
4. Deploy it as a web app with "Execute as: Me" and "Who has access: Anyone with the link".
5. Test the deployed `/exec` URL, not the editor-only `/dev` URL, plus `?mode=manifest&token=SECRET` in a private browser window. It must return JSON without a Google login, permission grant, or popup.
6. Enter the web app `/exec` URL and the same token on the frame config page.

If the test URL asks for Google authorization, the deployment is not usable by the Inkplate. Recheck that the web app runs as you, that access is public/link-based, and that you created a new deployment version after editing the script. Some Google Workspace domains block public Apps Script web apps; in that case use a personal Google account or a different manifest host.

The Apps Script exposes:

```text
?mode=manifest&token=SECRET
?mode=file&id=DRIVE_FILE_ID&token=SECRET
```

The manifest includes `id`, `name`, `modified`, and `size`. The Inkplate saves `/frame/sync_state.json` and downloads only missing or changed files. The config page controls how often the frame checks Drive; set "Sync every display updates" to `1` to check on every wake. Keep the Drive sync folder focused; the example processes up to 48 supported files and uses a 60 second HTTP read timeout for Apps Script cold starts.

Apps Script sends file content as base64 text, which is about 33% larger on the wire than the original file. Very large phone JPEGs can be slow or unreliable on the ESP32 and do not render as well as preprocessed frames. Prefer syncing `.bin` files or resized JPEGs under a few MB. A generated `.bin` frame is about 0.96 MB.

Apps Script does not include a Pillow/canvas-quality pixel pipeline, so the included script does not convert Drive images to BIN by itself. For a Drive-first workflow, run the Python converter against a local Google Drive synced folder so it creates `.bin` siblings. In `google_drive_apps_script.gs`, set `MANIFEST_BIN_ONLY = true` when you want the Inkplate to see only generated BIN files. Leave `HIDE_SOURCE_IMAGES_WHEN_BIN_EXISTS = true` to hide JPG/PNG/BMP originals whenever a matching BIN sibling exists.

## Unsplash Random Photo Sync

The frame can also fetch images with Unsplash's "Get a random photo" API. Create an Unsplash developer application, copy its Access Key, then open config mode and set "Web photo source" to "Unsplash random photo". The key is stored in `/frame/config.json`; do not commit or share that file.

Useful defaults for the 13SPECTRA panel:

```text
Orientation: landscape
Output width/height: 1600 x 1200
JPEG quality: 85
```

You can optionally constrain random results with exactly one filter: query text, topic IDs, or collection IDs. The Unsplash API does not allow those filters to be combined, so the config page clears the other filter fields when you type in one; saved configs keep collection IDs first, then topic IDs, then query text if multiple values are somehow present. Topic and collection fields expect Unsplash IDs, so look them up offline from Unsplash before pasting them into the frame UI.

Each sync downloads one random JPEG to the configured SD photo folder as `unsplash_<id>_<width>x<height>.jpg`. The sketch asks Unsplash for a cropped JPEG at the requested resolution and triggers the Unsplash download tracking endpoint as required by their API guidelines.

Spectra 6 generally looks cleaner with graphic art, illustration, posters, and low-noise images than with very detailed phone photos. Unsplash sync is useful for fresh artwork, but the best color control still comes from preprocessing selected images into `.bin` files with the Python converter.

## Config Mode

On first boot, the frame starts an access point named `Inkplate13Frame` with password `inkplate13`. Open the IP shown on the display, usually `http://192.168.4.1`. Configure Wi-Fi, web photo source, Drive or Unsplash credentials, sync cadence, photo folder, shuffle mode, update interval, and low-battery threshold. After Wi-Fi is configured, config mode first tries the home network and disables the setup AP when the connection works; the display shows the home-network URL. If Wi-Fi is missing or fails, the fallback AP is enabled again.

To force config mode later, press the Inkplate 13SPECTRA WAKE button while the frame is sleeping; the sketch enables GPIO18 as a config-mode wake source. While config mode is running, press WAKE again to close the web UI and return to photo display mode. You can also create an empty file at `/frame/config_mode.txt`. The library does not expose a clear USB/VBUS detect pin for this board; if your hardware revision exposes one, set `USB_POWER_DETECT_PIN` near the top of the sketch so USB power automatically enters config mode.

The config page shows the tail of `/frame/sync_debug.log`, and the same debug lines are printed to Serial at 115200 baud. Open `/log` for the full recent sync log and `/manifest_response` for the raw response captured from the last Drive manifest or Unsplash API request. Tokens are redacted from logged URLs. The "Sync photos now" button queues sync and returns immediately; while sync runs, `/log` remains available and SD-mutating commands are rejected until sync completes.

The config screen also renders a compact Spectra 6 profiling chart in the unused right-side area. Photograph that chart with a ColorChecker under your normal viewing light, then use `panel_profile.py measure` to create a panel profile for the BIN converter.

In normal frame mode, the sketch displays a local photo first, then runs scheduled sync with that photo left on the e-paper panel. If no local photos exist yet, it may sync before the first photo display.

## File Management

The config page includes an SD file manager scoped to the configured photo folder. Use it to upload `.bin`, `.jpg`, `.jpeg`, `.png`, or `.bmp` images, create subfolders, delete individual image files, recursively delete subfolders, or reset the local image cache. Cache reset deletes supported image files plus image `.tmp`/`.upload` leftovers under the photo folder and clears Drive sync metadata, but keeps folders, settings, logs, and the photo root. Photo playback scans subfolders too. Deleting the photo root itself is blocked so settings and sync state stay intact.

## BIN Conversion

Install Pillow, then convert images:

```sh
pip3 install Pillow
python3 tools/convert_to_inkplate13spectra_bin.py photo.jpg /Volumes/SDCARD/frame/photos/photo.bin --preview photo_preview.png
```

Batch convert a folder, including `~`, relative, absolute, directory, and glob inputs:

```sh
python3 tools/convert_to_inkplate13spectra_bin.py ~/Pictures/frame --recursive
python3 tools/convert_to_inkplate13spectra_bin.py "./photos/*.jpg" --output-dir /Volumes/SDCARD/frame/photos
```

The converter defaults to the recommended photo-frame quality path: `--orientation auto`, using a 1600x1200 landscape canvas for wide images and a 1200x1600 portrait canvas for tall images. It defaults to `--fit contain` so artwork and family photos are not cropped; use `--fit cover` when you prefer full-screen crop. Default rendering applies Lanczos resize, an `epdoptimize`-style photo-frame palette, `--color-matching lab`, display-range mapping with `--display-gamma 1.15`, `--contrast 1.0`, `--saturation 1.0`, `--red-saturation-scale 0.85`, `--sharpen 0.50`, Stucki error diffusion, stricter neutral/shadow protection, scarce-ink bias for red/yellow/blue/green/black, and light edge cleanup. This preserves gray and skin midtones better while still giving photos multi-color residual diffusion. Runtime JPG/PNG/BMP rendering is a fallback path; it now uses the same red-conservative palette matching, but it does not perform high-quality aspect-fit resizing or the converter's full tone pipeline.

For best color matching, measure your exact panel and viewing light with `panel_profile.py`, then pass the generated JSON profile:

```sh
python3 panel_profile.py chart --width 1200 --height 1600 -o chart.png
python3 panel_profile.py measure --panel panel.ARW --checker checker.ARW -o spectra6_profile.json
python3 tools/convert_to_inkplate13spectra_bin.py ~/Pictures/frame --recursive --panel-profile spectra6_profile.json
```

Without a measured profile, the converter uses `--palette-preset photo-frame`, which keeps calibrated Spectra 6 matching colors but reserves red ink for strongly red source pixels. Other built-in choices are `epdoptimize-boeber`, `epdoptimize-spectra6`, `epdoptimize-aitjcize`, `epdoptimize-legacy`, and `nominal`. The profile replaces built-in RGB primaries with measured Spectra 6 ink colors during quantization and preview generation. Profiles may use `panel_profile.py` fields such as `srgb8`/`Lab_D65` or epdoptimize-style `color` fields like `"#B9C7C9"`; entries are matched by `name`, not file order. The converter's logical palette order is black, white, yellow, red, blue, green, but the packed `.bin` payload stores raw 13SPECTRA framebuffer codes: black=0, white=1, yellow=2, red=3, blue=5, green=6. Regenerate older `.bin` files after this fix so blue and green are packed with the correct native codes.

Useful quality controls:

```sh
--color-matching lab                 # rgb is punchier; chroma is for saturated art
--dynamic-range display              # off, display, or auto percentile fitting
--dynamic-range-strength 1.0         # map source luma into the panel gamut
--display-gamma 1.15                 # values above 1 darken midtones before quantization
--edge-cleanup-strength 0.25         # reduce colored dither fuzz on strong edges
--dither stucki                      # coverage can reduce collapse but may create white dots
--diffusion-strength 0.85            # luma error diffusion; lower is cleaner but less tone-accurate
--chroma-diffusion-strength 0.10     # lower reduces red/green/blue speckling
--neutral-diffusion-strength 1.0     # keep gray tones from collapsing to solid white
--neutral-threshold 16               # protect near-gray regions from colored speckles
--neutral-saturation 0.16            # protect low-saturation regions without catching most skin
--shadow-neutral-max 88              # protect low-saturation dark regions
--shadow-neutral-saturation 0.42
--palette-preset photo-frame
--contrast 1.0 --saturation 1.0 --red-saturation-scale 0.85 --sharpen 0.50
```

For slightly more color detail at the cost of more speckling, try `--color-matching rgb --chroma-diffusion-strength 0.25`. If faces still look too pale with a measured profile, raise `--display-gamma` toward `1.30` or lower `--brightness` slightly. For stronger red output, raise `--red-saturation-scale` toward `1.0` or try `--palette-preset epdoptimize-boeber`. For illustration-style pastel preservation, try `--color-matching chroma`, but avoid it as the default for family photos because it can use much more color ink. Use `--dither coverage` only when a flat-color image collapses into a single ink and white-dot texture is acceptable.
